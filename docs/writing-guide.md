# How we write

A guide for every piece of text with the Better Code name on it: the website, emails, proposals, a LinkedIn post, a talk abstract. It sits next to the [design guidelines](design/design-guidelines.md), which cover how things look.

The goal is text that sounds like Max: a senior engineer explaining something to a colleague over coffee. Clear, specific, a little dry. Text should never read as if a machine or a marketing department wrote it, even when a machine helped.

## 1. The voice

- **First person, singular.** "I build…", "my company". Better Code is one person, so "we" only when it really means Max together with a client or team.
- **Plain, specific, calm.** Say the actual thing: "TypeScript, Java and Kotlin" rather than "a broad range of modern languages".
- **Confident without selling.** State what Max does and has done. Let the reader decide whether it's impressive.
- **A little dry humour is welcome** when it comes naturally ("This test failed" on the 404 page). Never forced, never emoji.

## 2. Headings

- **Headings are labels or short phrases, not sentences with a full stop.** "From the code up to the team", "Get in touch".
- **Sentence case:** only the first word and names get capitals.
- **No question headings** ("Why Better Code?") and no exclamation marks.
- **No colon reveals** ("Better Code: where quality meets speed").

Why no full stops: a full stop after every heading is a recent fashion in marketing sites and in AI-generated copy. One stop, used for effect, can work. A stop on every heading reads like a template.

## 3. Sentences and paragraphs

- **One idea per paragraph**, two to four sentences.
- **Vary sentence length.** A run of equally long, balanced sentences is the most common sign of generated text.
- **Contractions are fine** ("I've", "don't", "it's"). They make the text sound spoken.
- **Active voice.** "I built", not "was built".
- **Numbers as digits** from 10 upwards, and for years, ages and versions everywhere.
- **British or American spelling, but the same one throughout a page.** The website uses British spelling, apart from technical terms.

## 4. Things that make text sound machine-written

Avoid these patterns. One on its own is harmless; three in a paragraph give the game away.

| Pattern | Example | Instead |
|---|---|---|
| Lists of exactly three, everywhere | "clear, tested and maintainable" | Name the one or two things that matter, or four if there are four |
| "Not just X, but Y" | "Not just code, but culture" | Say Y |
| Colon reveals | "The secret: small steps" | "Small steps are what make it work" |
| Em dashes as all-purpose glue | "Code — and the teams — that last" | Commas, full stops or brackets. The website uses none. |
| Balanced antitheses | "Less ceremony, more delivery" | A concrete example |
| Grand openers | "In today's fast-paced digital landscape…" | Start with the point |
| Hype and filler words | *passionate, seamless, robust, cutting-edge, leverage, empower, unlock, delve, journey, elevate, world-class, solutions, synergy* | The specific noun or verb |
| Hedge stacks | "can potentially help to improve" | "improves", or say when it doesn't |
| Wrap-up sentences that repeat the paragraph | "In short, quality matters." | Stop one sentence earlier |
| Rhetorical questions | "Want better software?" | A statement |

## 5. Facts and claims

- **Only claim what can be backed up.** "More than 20 years" is fine because it is true. "Industry-leading" is not a fact.
- **No client names** unless the client has agreed and someone will keep the text up to date. Current assignments belong on the Crisp profile.
- **Keep text timeless where possible.** Prefer "since 2011" to "for 15 years", and a date to "recently". Relative times go stale.
- **Crisp:** Max is a consultant at Crisp and one of its co-owners. Crisp has no employees, so never call Max a Crisp employee and never call Crisp an agency or "just a network". (Details in the [design guidelines, section 12](design/design-guidelines.md#12-writing-about-crisp).)
- **AI:** say plainly how it is used. "I rarely type the code by hand any more" is honest and specific. Don't oversell ("10× productivity") or apologise.

## 6. Links and calls to action

- **Link text says where it goes:** "my profile on crisp.se", not "click here" or "read more".
- **One main call to action per page.** On the website it is email.
- **Write out email addresses in full** in text people will copy.

## 7. Using AI to write

AI tools are fine for drafts. The text is still ours, so:

1. Start from what you actually want to say, in your own rough words, and let the tool tidy it. Don't start from the tool's draft.
2. Cut a third. Generated text is nearly always too long.
3. Check every fact and number against the source.
4. Read it aloud. Anything you wouldn't say to a colleague goes.
5. Run the checklist in section 4.

## 8. Checklist

- [ ] Would Max say this out loud, in these words?
- [ ] Headings: short, sentence case, no full stop, no question, no colon reveal.
- [ ] No pattern from section 4 more than once on the page.
- [ ] Every claim is true and specific; no client names; nothing that goes stale.
- [ ] Links say where they go.
- [ ] Spelling consistent; spaces right next to links and punctuation (`npm test` checks the website for words running into links).
